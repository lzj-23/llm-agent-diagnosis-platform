# 完整开发计划

这是前期计划存档。最终按用户确认的十二阶段执行，当前验收与实际限制见 STAGE_GATES.md 和 SYSTEM_DESIGN.md；下方早期设想不作为已实现功能声明。

## 阶段 0：前期准备（已完成）

- 确定范围、边界和成功标准
- 只读盘点既有项目
- 建立架构、领域模型和后端骨架
- 建立测试、环境样例和基础设施配置

## 阶段 1：诊断工具层

- 定义统一日志和指标 DTO
- 实现 JSON/JSONL 导入与字段校验
- 实现异常阈值、分位数比较、错误聚合和时间窗口分析
- 创建四组合成 fixture 和工具单测

退出条件：不调用大模型也能从合成数据稳定生成事实摘要。

## 阶段 2：单 Agent MVP

- 接入 OpenAI 兼容模型接口
- 实现工具选择、结构化输出和超时处理
- 完成“提交任务—分析—返回报告”闭环
- 记录 token、耗时和错误

退出条件：单 Agent 在四个场景中能引用工具事实，失败时可降级。

## 阶段 3：多 Agent 编排

- 实现指标、日志、知识、诊断、审核和报告角色
- 定义共享状态和状态迁移
- 支持并行分析、冲突合并、重试和部分成功
- 对比单 Agent 与多 Agent 的质量、耗时和成本

退出条件：多 Agent 的收益用评测证明，而不是只展示调用链。

## 阶段 4：知识检索

- 建立排障知识库的加载、切分、检索与引用
- 接入既有 RAG 结果适配器
- 防止引用缺失、来源错配和检索无结果

退出条件：报告中的知识性建议能回溯到具体来源。

## 阶段 5：服务化与持久化

- PostgreSQL 数据模型和迁移
- Redis 队列、缓存和幂等控制
- 异步任务 API、分页查询和任务取消
- 鉴权、限流、输入大小限制和日志脱敏

退出条件：服务重启后任务和证据仍可查询。

## 阶段 6：前端

- 任务创建页
- Agent 执行轨迹和证据链
- 指标图表、报告页和历史任务页
- 失败/空状态和移动端基础适配

退出条件：用户无需直接调用 API 即可完成完整流程。

## 阶段 7：系统评测

- 建立有标注的故障场景集
- 评测异常识别、根因 Top-K、证据覆盖、建议可执行性
- 测量 P50/P95 耗时、成功率和成本
- 做消融：无 RAG、无审核、单 Agent、多 Agent

退出条件：所有简历数字都有脚本、数据和结果文件支持。

## 阶段 8：交付

- 后端和前端容器化
- CI 执行 lint、test 和安全检查
- 完整 README、架构图、演示数据和操作视频
- 整理简历描述、项目讲解和面试问答
- 用户确认后再创建 GitHub 远程并推送

## 开发原则

- 每个阶段先有可判定的测试场景，再实现功能
- 真实指标等实测后填写，不预设漂亮数字
- 提交记录反映实际开发步骤，不伪造历史
- 用户应能运行、解释并修改每个核心模块
