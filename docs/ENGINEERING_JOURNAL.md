# 开发问题与面试过程记录

## 记录规则

每个开发阶段结束时更新本文件。实际故障、方案选择和预期风险分别记录，失败尝试也保留。每条实际问题包含：触发场景、现象、假设、排查依据、根因或未确认原因、修改、验证结果、局限、相关文件或测试，以及可复述的面试回答。

禁止记录密钥、个人账号资料、支付信息和未脱敏日志。指标必须说明条件与测量范围；没有验证的问题不能写成已解决。面试口述是学习材料，实际操作参与程度必须如实说明。

## 2026-09-14：准备与模型连接

### E001：切换工作目录后，相对 Python 路径失效

- 场景：执行健康接口检查时，先设置相对路径 `.venv/Scripts/python.exe`，再切换到 backend 目录。
- 现象：PowerShell 提示找不到该可执行文件，检查未执行。
- 排查：虚拟环境此前安装成功，测试脚本可运行；出错命令在改变工作目录后才解析相对路径。
- 根因：相对路径基于当前工作目录解析，而不是声明变量时的目录。
- 修改：先解析项目根目录，用 Join-Path 生成 Python 的绝对路径，再切换目录执行。
- 验证：健康接口返回 status=ok；当轮 pytest 为 3 passed，ruff 通过。
- 边界：这验证了基础接口，不代表诊断功能已经实现。
- 证据：本次开发会话命令与输出；scripts/test.ps1 已使用基于 PSScriptRoot 的路径。
- 面试复述：我先确认虚拟环境本身可以运行，接着比较成功脚本和失败命令的工作目录，发现相对路径随着目录切换失效。最后改成从项目根目录构造绝对路径，再运行健康接口验证。

### E002：PowerShell 脚本需要检查外部命令退出码

- 类型：代码审查发现的可靠性缺口，没有实际注入失败进行回归验证。
- 现象与依据：最初的安装、检查脚本只设置 ErrorActionPreference，没有在 pip、ruff、pytest 后检查 LASTEXITCODE。
- 风险：外部程序失败时，脚本仍可能继续并输出成功提示。
- 修改：安装和测试脚本增加非零退出码检查，并抛出明确错误。
- 验证：正常执行路径通过；失败路径注入测试尚未做。
- 相关文件：scripts/bootstrap.ps1、scripts/test.ps1。
- 面试复述：我检查开发脚本时发现，仅设置 PowerShell 的异常策略不能替代外部程序退出码检查，所以在安装和测试命令后补了检查。正常路径已经验证，失败路径还需要专门测试。

### E003：第三方测试依赖出现弃用警告

- 现象：TestClient 相关依赖提示 httpx 和 BlockingPortal 接口弃用；测试仍为 3 passed。
- 当前处理：在 pytest 配置中精确过滤了这两条警告。
- 状态：只处理了测试输出，依赖兼容问题没有根治；直接运行连接检查仍可能显示警告。
- 后续：评估兼容的依赖组合，固定可复现版本，升级后重新验证；不能将过滤警告描述为修复依赖。
- 相关文件：backend/pyproject.toml。

### E004：本地模型凭据配置与首次连通验证

- 场景：用户创建百炼密钥，手动保存到 backend/.env。
- 配置依据：启动脚本切换到 backend，而 Settings 从当前目录读取 .env，因此将真实配置保存在 backend/.env。
- 操作：读取配置但不输出密钥，用 HTTP 客户端发送一句最小测试问题。
- 验证：HTTP 200，模型回复 OK；usage 为输入 66、输出 34、合计 100 tokens，其中 reasoning_tokens 为 31。输出用量并不等于用户看到的两个字符。
- Git 检查：git check-ignore 确认 backend/.env 被忽略。
- 边界：只验证身份、地址和当时模型调用可用；尚未验证工具调用、结构化输出、长上下文、并发或余额能支持多少任务。该检查是会话内临时命令，尚未保存为可复现测试脚本。
- 后续：建立脱敏的可选集成检查脚本和实际用量记录；统一配置加载路径，避免不同启动目录带来差异。
- 面试复述：我先用最小请求验证服务地址、密钥和模型名称是否匹配，接着检查返回状态、文本和实际 token 用量，最后确认密钥文件不会被 Git 跟踪。这个测试只证明连通性，Agent 的功能还要单独验证。

## 准备期风险清单（部分现已通过故障注入验证，见后文）

| 风险 | 自己重做时的排查方向 | 后续验收办法 |
| --- | --- | --- |
| API 余额不足或权限错误 | 区分 401/403、欠费错误和网络错误，核对模型权限 | 模拟拒绝响应，验证任务保留状态且不无限重试 |
| 限流与超时 | 检查并发、超时、重试次数，区分可重试与不可重试错误 | 注入 429、5xx、超时，测量重试上限 |
| Agent 循环调用导致费用上涨 | 查看每一步工具选择、调用次数和 token 用量 | 限制步骤与预算，触达限制时安全退出 |
| 模型输出字段缺失或格式错误 | 对照 schema 与原始脱敏响应 | 注入缺字段、错误类型和无效 JSON |
| 看似合理但没有证据的结论 | 检查引用是否存在、指标条件是否可比 | 构造无证据和冲突证据案例，要求拒绝下定论 |
| 检索资料不相关 | 检查切分、召回与重排，而非只修改提示词 | 使用固定问题集评测召回和引用正确性 |
| 多 Agent 状态覆盖与重复执行 | 检查任务 ID、状态迁移、幂等键和事务 | 并发提交、重复请求和中断恢复测试 |
| 进程中断导致结果丢失 | 确认哪些步骤已持久化，哪些外部请求状态不明 | 中途停止进程再恢复，核对重复调用与结果一致性 |
| 日志里的恶意指令影响 Agent | 将日志当数据，工具由权限白名单限制 | 注入伪造指令，验证不会越权调用工具 |
| 本地成功、其他机器失败 | 核对依赖版本、工作目录、环境变量和端口 | 从干净环境按 README 完整复现 |
