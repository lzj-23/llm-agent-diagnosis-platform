# 开发复核：不是独立人工盲评

复核范围：final-ablation 的 16 份最终报告的 conclusion、recommendations、uncertainty。审阅方式为开发助手逐项对照案例值；并非真实用户评分、独立专家评价或完整原子论断标注。没有把下面结果计成“零幻觉”。

| 报告 | 发现与判断 |
|---|---|
| single-latency-0 | waiting=28 与 max_num_seqs=16 “一致”、约一半请求等待不受证据支持；“非 OOM/抢占”排除过强。 |
| single-oom-0 | OOM 与 +6800 MiB、成功率 0.65 有依据；gpu_memory_utilization 与总峰值并不能简单直接比较，建议保留为预算核查假设。 |
| single-config-0 | 输入 32768 超过 max_model_len 2048 有直接日志支持；“排除 OOM 或性能退化”范围过大。 |
| single-normal-0 | 与基线一致及正常类别有依据；“已测量证据”应改为提供的合成证据。 |
| multi-latency-0 | 延迟差值正确，根因注明候选；用 4.2 req/s 描述有效并发上限存在量纲混淆，吞吐不等于并发。 |
| multi-oom-0 | OOM 与显存增长有依据；具体泄漏/驱动/输入模式均明确候选，没有证明具体原因。 |
| multi-config-0 | 配置不匹配有依据；前置拦截可作为合理解释，但“而非性能瓶颈或运行时 OOM”不能作全系统排除。 |
| multi-normal-0 | 清楚限定合成指标与空日志；没有推出整个生产系统一定健康。 |
| no-rag-latency-0 | 数值与排队现象有依据；明确调度容量只是候选，仍需复测。 |
| no-rag-oom-0 | 事实数值正确；nvidia-smi dmon 不提供张量级分配快照，工具能力描述不准确。 |
| no-rag-config-0 | 长度拒绝有依据；“单次请求”不是完整请求计数证据，只有一条摘录日志，不能外推样本数。 |
| no-rag-normal-0 | 正常类别且明确离线/合成边界，未发现明显数值冲突。 |
| no-reviewer-latency-0 | “等待而非计算瓶颈”排除无依据；计算饱和也可能引起排队。 |
| no-reviewer-oom-0 | OOM 事实正确；“而非配置错误”排除过强，静态配置一致不排除不合理配置共同作用。 |
| no-reviewer-config-0 | “排除 OOM 风险”与自身后文需监控显存的建议矛盾，审核有必要。 |
| no-reviewer-normal-0 | 现有数据无异常是合理结论；空日志不等于“日志数据缺失”，两者需要区分。 |

结论：类别命中率高不等于诊断语义质量高。Reviewer 在部分报告中改善了边界，但仍会漏掉量纲、工具能力与过强排除。当前版本必须由人确认建议，不应自动执行生产操作。

后续修复方向：将数字差值和单位检查移到确定性代码；增加“吞吐≠并发”“无日志≠无风险”的回归案例；扩展独立人工 rubric。保留本轮原始输出，不用修改 JSON 的方式让评测看起来更好。
