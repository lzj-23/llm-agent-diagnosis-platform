# 报告与证据逐条核对

## 新增机制

原检查主要验证引用ID存在和少量关键词，不能识别“而非其他瓶颈”这种不充分推断。现在默认开启semantic_review：结论、建议、验证步骤和不确定性按句号/分号切成片段，每批最多4片段，总计最多24片段。较长报告转人工，不静默省略。

核对器只能看到报告实际引用的、工具已返回的证据，不接收预期类别标签或历史记忆。它为每个片段给supported、hypothesis或unsupported及理由。一个片段内只要有一个无依据的事实断言，应判unsupported。hypothesis也用于明确的未来建议、验证步骤和不确定性，不等于原因已确认。

程序验证每个片段ID恰好出现一次；supported必须有非空、真实且已声明的引用ID。重复、漏项、虚构引用、无效JSON、超时和预算失败均转人工，取消请求继续向上传播。

报告最多修订一次。修订后再次检查，不因改写过就放行。最终核对表显示原片段、核对标签、引用和理由；原报告、修订、审计及调用费用保留在事件中。

## 算术与边界

显式的“从A秒变到B秒，增加/减少C秒”由Decimal校验，支持秒/毫秒转换。只核对明确匹配的时间增减表达，不推断无关数字、约数或复杂公式；没有匹配不代表所有算术都正确。

semantic_review=False可以在直接调用Engine时关闭该环节。默认开启它后，单Agent也会额外调用核对器，因此旧的单Agent开销不能直接对比。当前评测清单记录该开关；no-reviewer仅关闭原草稿Reviewer，不关闭最终核对。

## 开发挑战与真实失败

data/grounding_challenges.json包含8条手写挑战，预先标明应拦截与不应拦截；不同于原有四种故障模板，但仍由开发者编写，不是独立盲测或真实事故集。

- grounding-v1：7/8符合预期，其中一条直接日志观察因核对输出不符合引用/覆盖约束而不可用。后续明确允许的顶层引用ID。
- grounding-v2：发现模型理由写“计算错误”但verdict仍为supported。不能把模型审计当客观真值。随后增加程序时间增减校验。
- grounding-v3：7/8符合预期，算术错误和历史排除推断挑战均拦截；“建议检查是否配置错误”仍有保守误报，完整输出保留。
- grounding-v3/tests.xml：78项自动测试通过，含默认集成路径、修订后重新核对、取消、覆盖与引用约束、单位转换和时间差计算。

## 冻结流程与页面验收

grounding-e2e记录源代码未改变：4个类别均命中，3/4自动完成，正常对照转人工。正常报告声称离线重放没有新观察，却没有声明对应引用；“检查空日志以排除静默错误”的建议也被标记。此批估算模型费0.093702元，平均61.92秒；只有4例，不推断生产延迟或成本。

grounding-neural为本机Compose的真实模型调用和神经检索任务，完成并保存结果；页面实际展示15个核对片段、标签、引用和理由。公开静态回放加入该保存案例，不开放实时付费接口。

开发者逐条阅读仍发现漏检：grounding-e2e的latency/config结论仍有“而非单请求计算变慢或显存瓶颈”“性能指标未受算力或资源瓶颈影响”等超出聚合证据的表达，核对器没有全部拦下。因此completion、模型核对标签、人工阅读发现分别记录，不能把3/4完成或7/8挑战符合预期写成诊断准确率。

## 限制

判断仍使用相同供应商和模型，可能共享偏差；核对覆盖完整不等于语义完全正确。片段可能包含多条原子事实，尚无独立标注的句级召回率。更严格的检查可能降低自动完成率、增加成本和延迟；人工复核入口仍必须保留。

此轮没有新增付费云服务器、真实GPU OOM实验或公网实时API。公网仍是历史静态回放，本机工作台提供新核对功能。
